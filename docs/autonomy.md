# Автономная работа Listing Suite: схема (предложение 19.10.2026)

Правила в коротком виде — AGENTS.md, раздел «Автономия». Здесь — как это
устроено и почему так. Схема повторяет Кабинет (kabinet-dashboard PR #328,
`docs/autonomy.md` там же); отличия Listing Suite названы ниже.

## Зачем

До 19.10.2026 каждый шаг ждал владельца, а о готовности агент сообщал в
чат, где сообщение тонет.

Владелец хочет, чтобы рутина шла сама: он видит итог и решает только то,
что требует решения. Цена ошибки при этом разная:

- опечатка в `docs/` безвредна;
- правка кода меняет то, что видит команда;
- отправка в Amazon меняет живой листинг клиента;
- вызов модели стоит денег;
- правка канона Ярослава нарушает прямой запрет владельца процесса.

Отсюда три уровня, а не одно общее правило.

**Мерж — только по «мержи #N», для любого уровня** (решение владельца
24.10.2026, после #172). С 19.10 по 24.10 уровень «сам» мержился без
команды после «ок» проверяющего и зелёного CI; это отменено. Сами идут
очередь, PR, проверка и сводка, а мерж — всегда словом владельца, в том
числе PR только с `TASKS.md` или `docs/`.

## Четыре части

1. **`TASKS.md` — очередь.** У каждой задачи — уровень и проверяемый
   критерий готовности. Например: «вес 8,2 кг, а 7,5 отклонён», а не
   «сделать приёмку». Агент может поднять уровень, опустить — только
   владелец. Это и есть договор: всё, чего нет в очереди, агент сам не
   начинает.
2. **Уровни в AGENTS.md** — «сам», «ждёт меня», «никогда сам». Уровень
   считается по ИЗМЕНЕНИЮ, а не по задаче. Задача «добавить перевод» может
   притащить правку страницы, и тогда PR целиком становится «ждёт меня».

   Уровень «сам» узкий, и его граница проверяема по diff — это и делает
   проверяющий:
   - `docs/` — только добавление;
   - `TASKS.md` — без понижения уровней;
   - комментарии;
   - недостающие переводы без смены смысла;
   - проверочные скрипты только на чтение.

   Уровень права мержить не даёт: он называет риск изменения для
   проверяющего и владельца. Проверяющий, `docs/autonomy.md` и сам раздел
   «Автономия» — всегда «ждёт меня»: агент не расширяет себе права.
3. **Агент-проверяющий** — `.claude/agents/pr-reviewer.md`, отдельный
   агент, который не писал PR. Он:
   - читает diff и правила;
   - определяет уровень изменения;
   - идёт по списку типовых поломок проекта (NaN из pandas, строки мимо
     `t()`, HTML в несколько строк, ключ виджета против `value`, фильтр из
     двух источников, «пусто» против «сломалось», колонка без
     `missing_columns`, `ast.parse` вместо `compile`);
   - требует зелёный CI (`.github/workflows/ci.yml`) на последнем коммите
     PR — без него «ок» не ставится;
   - прогоняет весь `tests/` у себя тем же `tests/run_all.py`;
   - пишет вердикт комментарием в PR.

   Почему отдельный агент: автор проверяет то, что помнит, а пропускает
   как раз то, что забыл. Вердикт в PR, а не в чате, — чтобы владелец
   видел его там, где мержит.
4. **Сводка в бот после цикла.** `scratchpad/cycle_report.py` собирает:
   - что сделано;
   - что смержено по команде владельца;
   - что ждёт владельца;
   - что не получилось.

   Отправляет задача Кабинета «Kabinet - Agent Cycle Report» в тот же бот.
   Канал записи пока не выбран (раздел ниже), и до решения скрипт только
   печатает сводку.

## Чем Listing Suite отличается от Кабинета

- **Бот и задача отправки — Кабинета.** Своих у Listing Suite нет и не
  нужно: владелец один, бот один. Шапка сводки получает приставку
  «Listing Suite · ». Чужих учётных данных агент не берёт: роль Кабинета из
  его `.mcp.json` владелец запретил (19.10.2026).
- **«Никогда сам» шире.** К секретам, входу и удалению добавлены:
  - **Канон Ярослава** — только чтение. Это решение владельца процесса
    AI Design, а не наше, поэтому не «ждёт меня»: разрешить правку не
    может и владелец Listing Suite. Обновление снимка прогоном
    `build_snapshot.py` по новому архиву Ярослава — не правка, это
    «ждёт меня».
  - **Отправка в Amazon** — пишет в живые листинги клиента.
  - **Вызовы моделей и всё, что тратит деньги или невосполнимую квоту**:
    генерация, перевод, аудит фото, агенты Паспорта, сбор ScrapingDog,
    запуск сборщика, запросы к Figma (6 в месяц на месте View).

  Тесты с подменённым провайдером разрешены и нужны: именно ими агент
  проверяет такой код, не тратя денег.
- **Миграции SQL и ребут Streamlit Cloud — «ждёт меня».** Миграция
  приходит PR. Применяет её агент, но только по команде владельца
  «применяй <имя файла>» и под учёткой владельца в Databricks, не под
  `claude_code_ro` (решение 21.10.2026). Первые так применённые —
  `2026-10-21_content_versions.sql` и `…_checks.sql`.
  Ребут делает владелец; агент только называет, когда он нужен (новые
  символы в `services/*`, новые ключи `i18n`).
- **Окна без мержа — 09:30–11:30 и 16:00–17:30 по Киеву, как у Кабинета**
  (решение владельца 21.10.2026). Сначала здесь стояло «окон нет»: без
  команды сливалось только то, что не меняет работу приложения. Владелец
  поправил: окна действуют для любого мержа. С 24.10.2026 мержа без команды
  нет вовсе — окна для каждого мержа по «мержи #N».

## Цикл

1. Прочитать `TASKS.md`, открытые PR и комментарии проверяющего.
2. Взять задачи по порядку очереди. «Ждёт меня» — довести до PR с
   проверкой и описанием «что проверено, что нет».
3. Проверяющий на каждый PR. Замечания — исправить, проверить заново.
4. Ничего не мержить: PR с «ок» и зелёным CI — в «Ждёт вас» сводки, мерж
   по «мержи #N».
5. Обновить `TASKS.md`.
6. Сводка в бот.

## Что сознательно НЕ автоматизируется

- Мерж любого PR — кода, миграций, настроек, правил, `docs/` и `TASKS.md` —
  только «мержи #N» (24.10.2026). Тесты ловят падения, но не неверные
  решения.
- Канон, Amazon, модели и траты, секреты, вход, удаление данных,
  сообщения людям — «никогда сам».
- Изменение самого раздела «Автономия» — только по «мержи»: агент не
  расширяет себе права.

## Канал записи сводки (предложение, не выполнено)

Решает владелец. Оба варианта не дают агенту Listing Suite ничего, кроме
одной таблицы сводок.

**А. Отдельная роль только на `kabinet_data.agent_cycle_reports`.**

- В базе Кабинета заводится роль, например `ls_cycle_report`. Ей даются:
  - `INSERT` на эту таблицу;
  - `USAGE` на её последовательность.

  Больше ничего: ни `SELECT`, ни других таблиц.
- Её строка подключения лежит в `.mcp.json` ЭТОГО репозитория отдельным
  сервером. Чужой файл не читается.
- Задача Кабинета не меняется.
- Цена:
  - у Listing Suite появляется вход в базу другого продукта, пусть и на
    одну вставку;
  - роль живёт в базе Кабинета, и её надо помнить при ревизии прав.

**Б. Таблица сводок в `listing_data`, читает её Кабинет.**

- Миграция Listing Suite заводит `listing_data.agent_cycle_reports` той же
  формы.
- Агент пишет туда под своей ролью в своей базе. Писать ему разрешается
  только эту таблицу.
- Задача «Kabinet - Agent Cycle Report» берёт неотправленное из двух
  источников. Принципалу задач Кабинета нужны на эту одну таблицу:
  - `SELECT`;
  - `UPDATE` на `sent_at`, `send_error`, `attempts`.
- Цена:
  - правка задачи и ноутбука Кабинета;
  - второе подключение в ней.

**Рекомендация — Б.** Агент Listing Suite не получает никакого входа в базу
Кабинета. Связь направлена от Кабинета, у которого и так есть секрет бота и
задача отправки. Права на чтение одной таблицы чужого продукта у принципала
задач — меньший риск, чем право на запись у агента. Оба варианта —
«никогда сам»: роли, гранты и секреты заводит владелец.

## Как включить

1. Владелец выбирает канал (А или Б) и заводит роль и гранты.
2. Мерж kabinet-dashboard #328, его SQL и задача отправки — по инструкции
   того PR. Для варианта Б — с правкой задачи под второй источник.
3. Отдельным PR («ждёт меня») — запись в `scratchpad/cycle_report.py` и,
   для варианта Б, миграция таблицы.
4. Пробная сводка с шапкой «Listing Suite · Пробная сводка» приходит в бот.

## Проверка скрипта миграций

`test_apply_migration.py` — `scratchpad/apply_migration.py` отказывает там, где
обязан (решение владельца 21.10.2026). Без базы и без сети, проверяется `vet()`:

- только файл прямо в `migrations/`, кабинетный SQL — отказ всегда;
- одна транзакция, внутри ни `END`, `ABORT`, `START`, `ROLLBACK`, ни `COMMIT`
  в теле DO;
- удаление данных и `DROP` — отказ, в том числе в телах DO и функций;
  пересоздание триггера — только пара «имя, таблица», `CREATE` до `COMMIT`;
- после `COMMIT` — только `SELECT` без изменяющих слов;
- разбор не обманывают комментарии в телах, `"a'b"`, `E'\''`, `x$a$`.

Пробы пишутся во временный корень, в настоящую `migrations/` — ничего. Мутации
лексера и правил валят свои проверки.

## Размер AGENTS.md (21.10.2026)

Решение владельца 21.10.2026: AGENTS.md — только правила и ссылки, меньше 60 тыс.
символов; подробности — в `docs/` по файлу на область (#165). Порог в
`test_autonomy.py` — 60 тыс.; проверяющий требует новое знание класть в файл области
в `docs/`, а список тестов вести в `docs/tests.md`.
