# SQP: пакетный сбор v2 — подробно

Перенесено из AGENTS.md 21.10.2026 дословно, раздел «SQP: пакетный сбор v2 (параллельная проверка с 03.10.2026)» (решение владельца: в AGENTS.md — правила и ссылки). Ссылки поправлены под папку `docs/`; содержание не менялось.


Ноутбук `Listing Suite SQP Loader v2` (джоба 45883686210360, 01:00 и 19:00 Kyiv) работает
РЯДОМ со старым `Listing Suite SQP Loader`, не вместо него: решение владельца — старый
выключается только после недели параллельной работы и только его словом. Поэтому v2 пишет
лишь в свои таблицы (`sqp_reports_v2` той же формы, что `sqp_reports`; очередь `sqp_batches`,
учёт `sqp_asin_weeks`, `sqp_stoplist`, предфильтр `scp_weekly`), старые только ЧИТАЕТ — и
только при догрузке истории, чтобы не просить второй раз собранное. Витрину Unity Catalog и
диагнозы (правило low_ctr) не трогает. Свою неделю собирает независимо от старого: иначе
сравнивать было бы нечего.

**Почему переписан.** Старый ставил один отчёт на ASIN × неделю, не успевал даже на шести
прогонах в сутки и при смене недели бросал недоделанное: на неделю 13.09 из 515 отчётов готово
184, а 283 не забраны никогда. Половина готовых — пустые (1 114 из 2 268): общую квоту
`createReport` тратили на товары без показов.

**Что проверено пробой 03.10.2026** (один пакет, неделя 20.09, Испания):

- параметр `asin` (в единственном числе) принимает до 18 ASIN через пробел, ≤200 знаков; ответ —
  один документ, строки разных товаров делятся по полю `asin` в `dataByAsin` без потерь;
- **невалидный ASIN пакет НЕ роняет**: Amazon отвечает DONE, отдаёт данные по остальным, а
  несуществующий просто пропадает из ответа. На практике это «нет данных», а не FATAL;
- пакет готовится за **30–40 секунд** от создания;
- потолок самого Amazon — 100 поисковых запросов на товар: ровно 100 строк приходит и в
  пакете, и в одиночном отчёте, это не потеря от пакетов;
- по общим ASIN данные совпали со старым загрузчиком ПОЛНОСТЬЮ: 48 пар из 48 — число запросов и
  суммы показов, кликов и покупок до единицы.

**Устройство.** Каждый прогон сначала опрашивает ВСЁ незавершённое (за любые недели — смена
недели очередь не обнуляет), потом ставит новое: запланированные половинки и созревшие повторы,
предфильтр SCP по рынкам, пакеты свежей недели (самые доходные — первыми, на всех рынках сразу),
затем историю с самых старых недель. Предфильтр: SQP запрашивается только по товарам с показами
в Search Catalog Performance той же недели; топ-50 пар «ASIN × рынок» по выручке за 90 дней
(Кабинет, `sales_traffic_asin`, в евро через `to_eur`) — каждую неделю, в обход фильтра.

**FATAL — по причине и по возрасту недели.** «A client error occurred…» Amazon присылает
одинаковый и на неопубликованный период, и на неверные параметры, поэтому свежая неделя с таким
текстом — «ещё не опубликовано», повтор через сутки, а старая — ошибка пакета: делим пополам, из
одного ASIN — в стоп-лист. Отказ createReport по существу (не 429) прогон не роняет: пакет
ложится в очередь со статусом `error` и текстом Amazon.

**У `getReportDocument` своя квота — одна в минуту с запасом в пятнадцать.** Первая редакция
v2 этого не учитывала и упала на шестнадцатом документе: `KeyError: 'url'` — 429 пришёл с телом
без ссылки. Старый загрузчик этого не видел, потому что спал по 65 секунд после каждого
скачивания. Теперь запас тратится сразу, дальше на 429 ждём по минуте; один неразобранный
документ не роняет опрос остальных — пакет остаётся в очереди с текстом ошибки. Проба на трёх
отчётах этого поймать не могла: квота кончается только на шестнадцатом.

**Сверка со старым — каждым прогоном**, снимок в `sqp_v2_compare` по свежей и предыдущей неделе:
запросы у обоих, собранное, совпадение по общим ASIN, топ-50 и четыре условия владельца
(`условия`): неделя собрана полностью без брошенных; топ-50 закрыты; по общим ASIN данные
совпадают; квоты не больше половины старого. Промежуточная сверка — 06.10, итог — 10.10.

Рынки — ES, DE, IT, FR, NL, SE, GB; PL, BE, IE исключены проверкой в коде (`assert`), потому что
SQP аккаунту по ним недоступен. У SE в матрице нет ни одного товара, так что по Швеции v2
собирает только предфильтр SCP.
