# Тесты (`tests/`) — подробно

Перенесено из AGENTS.md 21.10.2026 дословно, раздел «Тесты (`tests/`)» (решение владельца: в AGENTS.md — правила и ссылки). Ссылки поправлены под папку `docs/`; содержание не менялось.


Запускаются как обычные скрипты, pytest не нужен и в зависимости
не добавлен. Весь набор одной командой — `python tests/run_all.py`
(слова после команды — фильтр по имени файла).

**CI** (`.github/workflows/ci.yml`, с 19.10.2026) гоняет тот же
`run_all.py` на каждый PR, на пуш в `main` и на ветки `ci-check/**`:
Python 3.12, Node 20 для плагина Figma. Базы и секретов в CI нет и не
будет — репозиторий публичный. Всё, что ходит наружу, подменено в самих
тестах. Если тест падает только без секретов — это поломка теста, а не
окружения: так было с `test_localization.py`, который ждал настоящих
ключей Figma (T-15).

В набор входят три проверки, которых нет у отдельных страниц:

- `test_syntax.py` — каждый `.py` из git компилируется (`compile`, а не
  `ast.parse`);
- `test_imports.py` — каждый модуль `services/`, `components/`, `i18n`,
  `config`, `auth`, `access_screen` импортируется в отдельном процессе с
  пустым окружением;
- переводы — `test_i18n_sync.py`: паритет ключей, дубли, плейсхолдеры.

`tests/fixture_pilot.py` — не тест, а данные пяти пилотных товаров ES в форме
базы: атрибуты SP-API, тайтл и поля снапшота, снятые чтением 20–21.10.2026.

`tests/fixture_template.py` — не тест, а общая миниатюра шаблона Amazon
для двух наборов сразу: импортировать один тест из другого нельзя,
они исполняются как скрипты.

`test_ai_errors.py` — регрессия на самый дорогой класс поломок:
**ошибка провайдера обязана доходить до экрана**. Проверяет HTTP-ошибку
с кодом и телом, HTTP 200 с неразобранным телом (раньше тихий `None`),
таймаут, сброс ошибки при успехе и главное — что сообщение переживает
`st.rerun()`. Ломать эти проверки нельзя: молчаливый провал генерации
стоил часов диагностики при починке в одну строку.

Отдельной проверкой заперт список задач ИИ: он живёт в `DEFAULTS`
(`services/ai.py`) и в `TASKS` (`pages/settings.py`), и разойтись им
достаточно один раз. Так и случилось с `translate`: в коде задача
была, в Настройках нет — модель выбрать нельзя, работает умолчание
из кода.

`test_flatfile_export.py` — выгрузка обязана быть настоящим файлом
Amazon: служебные строки 1–6 доходят без правок, колонки ищутся по
машинному имени из строки 5, подпись частичного обновления берётся из
шаблона, а не хардкодится, строка с непокрытым типом товара попадает
в список проблем, а не теряется.

`test_synthesis_counters.py` — числа в шапке Синтеза проверяемы.
Рядом с разрезом по стране стоит общее число: пока было видно только
общее, неверный разрез выглядел бы нормально. Проверяет, что фильтр
режет ВСЕ три метрики (деньги, тайтлы, SQP), что общее от фильтра
не едет и что без фильтра «всего» не показывается.

`test_synthesis_breakdown.py` — разрез по рынкам и происхождение
черновика. Строки таблицы по странам обязаны складываться в итог —
это и есть проверка разреза. Плюс честность подписей: «Прочие»
перечисляют коды свёрнутых стран, выбранная страна не сворачивается,
плашка модели не выдумывает вендора для незнакомого имени, а история
не пишет «отклонено» — отказ нигде не сохраняется.

`test_prompt_cache.py` — кэш промпта живёт на совпадении байтов.
Половина проверок про то, что кэш работает (постоянная часть побайтово
одна на все товары, тайтл и фразы в неё не попадают), половина — что он
инвалидируется: правка методологии или смена её версии меняют байты.
Без второго генерации молча шли бы по старой методологии.

`test_push_amazon.py` — отправка пишет в ЖИВЫЕ листинги клиента,
поэтому главная проверка не «работает ли», а «не срабатывает ли сама»:
отрисовка подтверждения не шлёт ничего, кнопка на панели только
открывает диалог, запрос уходит лишь после второй кнопки. Плюс
marketplace_id только из шаблона, тайтл сверх лимита не отправляется,
Highlights не уходят без укладывающегося тайтла, журнал пишется и при
отказе.

`test_catalog_choice.py` — плашки Amazon's Choice. Три случая ломаются
тихо: NaN у несобранного товара истинный и дал бы «бейдж есть» без
данных; боль `lost_amazon_choice` живёт до следующего сбора, и красная
«потерян» рядом с вернувшимся бейджем — враньё; отсутствие бейджа
не показывается вовсе, иначе шум прячет сигнал.

`test_manual_edit.py` — ручная правка в карточке результата. Источник
в `synthesis_changes` считается по ФАКТИЧЕСКОМУ тексту, а не по тому,
что форму открывали: иначе доля ручных правок — мера попадания
методологии — врёт в обе стороны. Плюс лимит длины руками не обходится.

`test_marketplace_maps.py` — маркетплейс живёт в ЧЕТЫРЁХ независимых
картах (подписи в `i18n`, `MP_COUNTRY` и `MP_LANGUAGE` в `matrix_setup`,
`MARKETPLACE_REGION` в `spapi`), и пропуск страны в каждой молчит
по-своему. Дороже всех `MP_COUNTRY`: фолбэк «us» уводит сбор
на amazon.com, и снапшот приезжает от чужого листинга. Тест проверяет
не подписи, а согласованность карт между собой.

`test_aplus_stable.py` — A+ читается из `listing_latest.has_aplus`,
а не из последнего снапшота. Ошибка тут не выглядит ошибкой: карточка
показывает «A+ нет», Диагноз заводит боль, человек идёт делать A+,
который уже есть. Проверяются обе стороны подмены и запасной путь
для товара первого сбора.

`test_card_actions.py` — область действия кнопок. В карточке они
работают по ОДНОМУ товару, наверху — по всем принятым под фильтром,
а называются почти одинаково. Проверяется не наличие кнопок, а размер
выборки: файл из карточки содержит одну строку при трёх принятых, файл
сверху — три. Отдельно — что карточка переживает приёмку: принятый
черновик выпадает из очереди разбора, и без третьего источника
(принятая правка) кнопки «после приёмки» были бы недостижимы.

`test_history.py` — история по товару из трёх таблиц. Порядок событий
тут не косметика: по нему видно, ушла ли в Amazon последняя принятая
правка или предыдущая. Плюс заходы считаются ПО ИНТЕРВАЛАМ между
приёмками (общий счётчик завысил бы вторую), отказ Amazon не выглядит
успехом, а недоступная история отличима от пустой.

`test_silent_failures.py` — сбой не должен выглядеть как «данных нет».
Самая дорогая из запертых здесь ошибок: сбой чтения SQP превращал
генерацию в работу вслепую — `keep=[]`, `forbid=[]`, `keeps_all` на пустом
списке проходит сам собой, тайтлы получаются в лимите и с зелёными
галочками, а поискового веса в них нет. Плюс `float(x or 0)` на NaN даёт
NaN, а не ноль, и правило без коэффициента больше не получает 3% выручки.

Второй половиной заперта разница между «пусто» и «сломалось» на трёх
страницах. Проверяется не наличие сообщения об ошибке, а ОТСУТСТВИЕ
совета собрать товары: при недоступной базе Каталог, Матрица и Фото
показывали «Данных ещё нет — соберите товары в Матрице», то есть звали
завести заново почти тысячу существующих пар. У Фото проверка отдельная
и по второму запросу: непрочитанный аудит выглядит как «без аудита»,
а это приглашение заплатить vision-модели за уже сделанное.

`test_methodology_guard.py` — генерация без методологии не запускается.
Инцидент 29.08: в тайтлы вернулся бренд, хотя активная v8 его запрещает.
Кэш промпта был ни при чём — в `load_skill()` жила ЗАПАСНАЯ методология
с зашитым «Бренд Dnipro-M первым», то есть с правилом, прямо
противоположным действующему. Включалась молча, уходила в промпт
с версией 0, и всё выглядело нормально. Запасной больше нет никакой,
версия 0 означает отказ.

`test_progress.py` — ход генерации виден, старый результат не мигает.
Дольше всего идут автоповторы, и раньше они шли молча: экран замирал,
и было не понять, работа идёт или сломалось. Проверяется не наличие
строк, а фактическая последовательность шагов, номер повтора с
превышением, и что сломанный показ хода не роняет саму генерацию.

`test_no_deprecations.py` — лог не должен зарастать предупреждениями.
Смысл не в аккуратности: предупреждения шли на каждый запрос, и в этом
шуме не видно настоящих ошибок. Проверяется грепом по исходникам —
важно не «работает», а «нигде не осталось»; плюс отдельно то, что
pandas через движок действительно молчит (остальные тесты подменяют
`pd.read_sql` и этого бы не увидели). С 26.09 здесь же — пустые
подписи виджетов: Streamlit пишет «`label` got an empty value» на
каждую и обещает сделать это ошибкой (одна галочка товара на
«Контенте» давала 49 таких строк за прогон тестов). Подпись можно
скрыть `label_visibility="collapsed"`, но не оставить пустой — её
читает экранный диктор; у галочек строк это «Выбрать: <товар>»
(`common.pick_row`). Проверка разбором кода (`ast`), а не грепом:
подпись часто стоит на следующей строке после скобки.

`test_card_states.py` — основная кнопка показывает СЛЕДУЮЩИЙ шаг.
Раньше «Принять» оставалась оранжевой у товара, который уже принят
и отправлен, то есть предлагала сделать сделанное. Проверяется вес
кнопок по protobuf, а не по подписи: подписи не менялись, менялась
иерархия. Плюс что плотность из PR #42 не сломана новой раскладкой.

`test_cache_invalidation.py` — сброс кэша не должен быть ковровым.
Проверяется не «есть ли кэш», а ЦЕНА действия в запросах: приёмка одного
тайтла стоила 10 запросов на трёх страницах, стала 1. Отдельно заперт
вывод, который легко потерять: переключение фильтра запросов НЕ делает,
поэтому добавлять фильтры в ключ кэша нельзя — каждая комбинация стала бы
отдельным запросом.

`test_figma_read.py` — чтение и разбор макетов. Три тихие поломки:
обход по верхнему уровню нашёл бы часть текстов и показал неполный
список полным; связь по имени фрейма увела бы тексты одного товара
к другому (`carousel 2.2` есть у многих — поэтому модуль A+ берёт
товар у подписи над собой, а без подписи уходит в сироты, не к
первому попавшемуся); предел символов, выдуманный
вместо «неизвестно», выглядел бы фактом. Отдельно заперт лимит
запросов: при 429 ретраев НЕТ и запрос ровно один — повтор внутри кода
только съел бы лимит и растянул ожидание. Сеть не трогается.

`test_localization.py` — контроль длины перевода и честность демо.
Ради колонки длины страница и делается: не влезший в слой текст
обнаруживается при экспорте, когда работа уже сделана. Проверяются
ответы расчёта — влезает, впритык, не влезает, предел неизвестен, —
и отдельно то, что нулевой предел не выглядит как «неизвестно» (ноль
в Python ложный, проверка через истинность их бы склеила). Вторая
половина про демо: оно обязано объявляться плашкой, а сбой чтения —
оставаться сбоем. Третья — про картинки: список показывает фото
Amazon и НЕ делает ни одного запроса к Figma (одна картинка на товар),
а отказ Figma миниатюру в списке не трогает.

`test_change_type_scope.py` — правки разных полей не смешиваются.
`synthesis_changes` одна на все поля листинга, различает их
`change_type`. Пока писался один тип, фильтра не было в двух местах, и
сработало бы это в день первого принятого буллета: карточка показала бы
его как принятый тайтл, счётчик длины считал бы «212/75», значок «тайтл
принят» встал бы товару, у которого тайтл не трогали. Проверяется
поведение: в базе лежит принятый буллет, и он не должен попасть никуда,
где ждут тайтл.

`test_resolved_pains.py` — закрытая боль не имеет права вернуться.
Боль закрывается, когда сбор её больше не находит, но запись остаётся
в `diagnosis` с `resolved_at`. Без фильтра закрытое возвращалось
на экран вместе с живым: товар с готовым A+ показывал «Нет A+
контента». Дороже самой ошибки то, что деньги под риском и счётчики
болей считаются по ТОМУ ЖЕ набору — завышенным было всё. Вторая
половина набора про обратную сторону: пустой ответ означает «проблем
нет», и страница рисует зелёное «✓ N товаров без болей», то есть при
недоступной базе УТВЕРЖДАЕТ, что всё в порядке.

`test_tables_photo_asin.py` — фото и кликабельный ASIN во всех списках.
Три свойства, и каждое ломается тихо: домен (у Бельгии ссылка вела
на несуществующий amazon.be), заглушка вместо пустой ячейки
(`ImageColumn` при пустом значении не отличает «фото нет» от «столбец
не про это») и КЛЮЧИ. Третье дороже всех: в Матрице по колонке `asin`
строились ключи для сбора и удаления, и подмена ASIN на ссылку дала бы
кнопку «Удалить выбранные», которая молча не удаляет ничего. Поэтому
проверяется не наличие ссылки, а то, что выбор строки по-прежнему
указывает на тот же товар.

`test_i18n_sync.py` — словарь и его рассинхрон с кодом. Паритет по
МНОЖЕСТВУ ключей слеп к дублям: ключ, объявленный в языке дважды,
оставляет последнее значение, а множества сходятся — так в английский
блок попали украинский и русский тексты того же ключа. Поэтому дубли
ищутся по СТРОКАМ файла. Вторая половина — про деплой: сайдбар
сравнивает ключи ФАЙЛА `i18n.py` с ключами модуля В ПАМЯТИ и говорит
«интерфейс новее модулей, нужен ребут». Судить по промахам `t()` нельзя,
и это заперто отдельной проверкой: первая версия детектора считала
промахи и объявила ребут на ровном месте — на штатных пробах вроде
`issue.code.100232`. Ложная тревога здесь дороже молчания: после неё
настоящую не воспримут всерьёз.

`test_methodology_page.py` — методология обязана доходить до экрана.
Инцидент 30.08: страница для ЛЮБОЙ области показывала «методологии ещё
нет» при живой v8 в базе — в загрузчике остался `conn.close()` от
прежнего способа чтения, и NameError уходил в общий `except`. Дороже
самой невидимости то, куда страница вела дальше: пустой редактор и
кнопка «Сохранить как v1», то есть сбой чтения подводил к ПОТЕРЕ
методологии. Теперь при сбое чтения редактор и сохранение заперты.
Вторая половина — реестр политик: таблицы `policy_alerts` в базе нет,
и страница обязана говорить «слежение не ведётся», а не «Новых
изменений нет — все источники соответствуют текущим методологиям».
Проверяется не наличие плашки, а ОТСУТСТВИЕ второй фразы: именно она
усыпляет, а политика по тайтлам от 27.07.2026 меняет то, что вообще
можно отправить в листинг.

`test_feed.py` — одна лента вместо трёх вкладок. Главная проверка не

`test_figma_plugin.py` — обход плагина совпадает с обходом Listing
Suite. Плагин кладёт перевод в слой, найденный по `slot`, и считает
слот САМ, на JavaScript, а Listing Suite считает его на Python при
чтении файла. Разойдутся — переводы встанут не в те строки, и это
худший исход: карточка выглядит правдоподобно. Поэтому проверяется

и пробельный текст, скрытый слой, INSTANCE, опечатка `BB0…`, два
фрейма с одним именем) скармливается обоим обходам, и списки
«slot → текст» обязаны совпасть буквально. JavaScript исполняется
по-настоящему — Node или JavaScriptCore через `osascript`; без
движка тест ПАДАЕТ, а не пропускает проверку. Мутация «порядковый
номер текстового слоя вместо пути» — та самая формулировка из
описания задачи — ловится первой же проверкой. Второе дерево — про
модули A+: подпись с типом и без, чужой блок выше низа слайдов,
десктоп/мобайл, ряд на границе сотни, сирота. Здесь расхождение ещё
правдоподобнее — перевод встаёт в чужой модуль того же товара, —
и заперты обе мутации: `Math.round` вместо `floor(x + 0.5)` и снятая
проверка «ниже слайдов».
