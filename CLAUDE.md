# CLAUDE.md

Listing Suite — Streamlit-приложение диагностики Amazon-листингов бренда
Dnipro-M. Данные — Databricks Lakebase (Postgres), схема `listing_data`.
Интерфейс на трёх языках: ru / uk / en.

Запуск: `streamlit run app.py`

Логика продукта: матрица товаров → сбор снапшота (ScrapingDog) → диагноз
(боли по правилам) → синтез правки (ИИ + проверки кодом) → принятая правка
→ снова сбор. Человек добавляет товары и принимает правки, остальное — код.

## Правила проекта

Выстраданы на практике. Нарушение каждого из них уже роняло страницу.

**0. Плотный ряд кнопок делается ФЛЕКСОМ, а не долями колонок.**
`st.columns` делит ширину по долям, а кнопка внутри растягивается на всю
долю — между подписями остаются пустые поля самих кнопок, и подбор долей
это не лечит. Нужно снять и то, и другое: колонке `flex:0 0 auto;
width:auto`, кнопке `width:auto`, последней колонке `flex:1 1 auto` под
остаток. Эталон — `.st-key-rescard-*` в
[pages/synthesis.py](pages/synthesis.py). Та же природа у `stButtonGroup`
из PR #14: контейнер раскладки распределяет, а не сжимает.

**1. HTML внутри `st.markdown` собирается ОДНОЙ строкой** — без переносов и
отступов. Эталон — [components/ui.py](components/ui.py) (`pain_card`,
`verdict`, `limit_ruler_html`): конкатенация f-строк, ни одного `\n` внутри
разметки.

Механика, чтобы правило не выглядело суеверием: `st.markdown` прогоняет
строку через `textwrap.dedent(...).strip()`, поэтому ровный общий отступ
многострочной f-строки срезается и разметка чаще всего выживает. Ломается
она на неровностях: подстановка, стоящая одна на строке, схлопывается
в пустую (нет линейки, нет значков) → пустая строка закрывает HTML-блок →
следующая строка, если её отступ после dedent ≥ 4 пробелов, становится
блоком кода, и пользователь видит текст разметки. Одна строка снимает весь
класс этих отказов разом.

**2. `MONO = "var(--ls-mono)"`** — CSS-переменная, объявленная в
`inject_fonts()` ([components/ui.py:41](components/ui.py:41)). Имя
`"JetBrains Mono"` содержит пробел и требует кавычек в CSS; кавычки внутри
HTML-атрибута рвут тег. Внутри атрибутов кавычек быть не должно.

**3. Имена колонок DataFrame — технические латиницей** (`img`, `len`, `risk`,
`link`). Человеческие подписи задаются ТОЛЬКО через `column_config`. Иначе при
переводе возникают дубли имён колонок и pyarrow роняет страницу с `ValueError`.
Эталон — `kw_editor` в [pages/synthesis.py:467](pages/synthesis.py:467) и
таблицы в [pages/catalog.py:330](pages/catalog.py:330),
[pages/dashboard.py:448](pages/dashboard.py:448).

**4. `pd.isna(x)` вместо `if x`** — NaN в Python истинный, `len(NaN)` роняет
страницу. См. [services/worklog.py:85](services/worklog.py:85),
[pages/matrix_setup.py:569](pages/matrix_setup.py:569).

**5. Все видимые пользователю строки идут через `t()`** из
[i18n.py](i18n.py). Наборы ключей в ru, uk, en должны совпадать, плейсхолдеры
тоже. Сейчас паритет полный: по 695 ключей в каждом языке, дублей нет.
Строка прямо в коде — это будущий непереведённый элемент.

Есть места, где отсутствие перевода ШТАТНО: подписи болей подставляются
по `rule_id`, коды проблем Amazon приходят сотнями. Такие места
спрашивают словарь через `i18n.tr_opt(key)` — «перевод или None» — и при
промахе берут запасной текст. Через `t()` их спрашивать нельзя: сайдбар
считает такие промахи признаком незавершённого деплоя.

**6. Палитра:**

| роль | цвет |
|---|---|
| фон | `#FAFAF8` |
| чернильный (текст) | `#1A1815` |
| акцент (только для боли) | `#E8590C` |
| зелёный (норма) | `#2F6B3A` |
| приглушённый | `#57534A` |
| границы | `#E7E4DD` |

Та же палитра продублирована в [.streamlit/config.toml](.streamlit/config.toml)
(тема Streamlit) и в константах наверху каждой страницы.

**7. Виджет выбора с переводимыми подписями хранит значение ОТДЕЛЬНО.**
Streamlit опознаёт виджет в том числе по подписям опций, а их даёт
`format_func` — то есть перевод. Сменил язык — подписи другие — виджет
считается новым и откатывается к default: фильтр рынка пропадал, хотя
чип на экране ещё висел. Эталон — `sticky_select` в
[pages/synthesis.py](pages/synthesis.py): выбор живёт кодами в своём
ключе, в виджет отдаётся через `session_state` (вместе с `default`
нельзя — Streamlit ругается), обратно приезжает колбэком, и колбэк
ИГНОРИРУЕТ значения, которых нет в опциях: пересоздавая виджет,
Streamlit присылает туда подписи прошлого языка.

## Подключение к данным

`services/db.py::get_conn()` — единственная точка входа для записи,
`get_engine()` — для чтения через pandas (движок SQLAlchemy поверх того же
`get_conn`, `NullPool`: у Lakebase токен живёт около часа, и соединение
из пула однажды переживёт его). Голое psycopg2-соединение в `pd.read_sql`
не передаётся — pandas на это предупреждает на каждый вызов. Три режима,
определяются автоматически в этом порядке:

1. **Notebook** (ноутбук Databricks): `LISTING_LAKEBASE_ENDPOINT` +
   `databricks.sdk` → OAuth-токен (~1 час, генерится на каждый вызов).
2. **Dashboard** (Streamlit Cloud): секция `[databricks]` в секретах →
   service principal OAuth.
3. **DSN** (локально): `DATABASE_URL` → `psycopg2.connect(url)`.

`search_path` всегда выставляется в `listing_data, public`, поэтому в SQL имена
таблиц пишутся без префикса схемы.

**Правило DDL: миграции идут через Databricks, вручную.** Каждая — отдельный
`.sql` в [migrations/](migrations/), см. [migrations/README.md](migrations/README.md).
Приложение схему не создаёт и не меняет — только `SELECT` и разрешённые
`INSERT`/`UPDATE`.

Раньше здесь значилась «единая точка миграций» `ensure_all_schemas()` из
ячейки ноутбука. Она не работала: все три её импорта падали, и четыре
миграции подряд прошли мимо неё. Функция удалена — механизм, который
не работает, но выглядит работающим, хуже отсутствующего.

Секреты читаются через `services.db.cfg(name)`: env → `.streamlit/secrets.toml`
на диске → `st.secrets` → default. Ключи: `SCRAPINGDOG_API_KEY`,
`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`.

## Страницы (`pages/`)

Регистрируются в [app.py](app.py) через `st.navigation`, два раздела:
«Работа» (guide, dashboard, catalog, synthesis, photo) и «Управление»
(matrix_setup, methodology, settings).

### `guide.py` — «Как это работает»
Статичная инструкция для команды: 6 шагов + анимированная схема потока
матрица → сбор → диагноз → синтез → Amazon. Живой статус на схеме
(свежесть сбора, число болей).
Читает: `listing_snapshots`, `diagnosis`.

### `dashboard.py` — «Диагноз» (страница по умолчанию)
Главный экран: сколько товаров требует внимания, деньги под риском, дельта
болей с прошлого прогона. Фильтры по severity / группе правила / маркетплейсу /
поиску, два вида (карточки и таблица), пагинация по 25. Внизу — счётчик
здоровых и несобранных. Показывает только проблемные товары.
Деньги под риском = выручка ASIN × коэффициент правила (`RULE_RISK`); по товару
берётся максимум, а не сумма — проблемы пересекаются.
Читает: `diagnosis`, `listing_snapshots`, `product_matrix`, `asin_economics`
(через `services.economics`), `app_settings` (через `services.settings`).

### `catalog.py` — «Каталог»

Паспорт каждого товара: тайтл, фото, видео, A+, отзывы, рейтинг, цена, BSR,
сток, продавец, экономика, SQP-метрики, атрибуты, Amazon's Choice. Показывает ВСЕ товары,
включая здоровых и конкурентов. Здоровье считает код (`health()`), не ИИ.
BSR парсится из `raw` регулярками, потому что ключ и формат зависят от языка
страницы.
Читает: `product_matrix`, `listing_snapshots`, плюс через сервисы —
`asin_economics`, `synthesis_drafts`, `synthesis_changes`, `photo_analysis`.
Атрибуты и поисковую сводку берёт из `services.attributes` и
`services.search`.

### `synthesis.py` — «Синтез»: Split 75/125
Словарь интерфейса: **«черновика» в UI нет**. То, что выдала модель, —
«результат», собирательно «Сгенерированные», счётно «сгенерировано: N».
Слово «черновик» читается как «набросок» и скрывает, что там готовый
результат, ждущий решения. В коде и в имени таблицы `synthesis_drafts`
оно остаётся — это внутреннее имя, а не то, что видит человек.
Разбивает длинный тайтл на `title` ≤ 75 символов и `Item Highlights` ≤ 125.
Смысл разделения: title читает человек за 1–2 фиксации взгляда, Highlights
парсит ИИ-ассистент покупателя (Rufus/COSMO).
Методология тянется из `synthesis_skill` (активная версия, правится на странице
«Методология» без коммитов). **Запасной методологии в коде нет намеренно:**
раньше при сбое чтения подставлялся зашитый текст «Бренд Dnipro-M первым» —
правило, противоположное действующей v8, — и подмена шла молча. Теперь
пустой текст или версия 0 означают «методологии нет», и генерация
не запускается вовсе. Защищённые фразы размечаются по фактам SQP
(`services.seo`), после генерации результат проверяется КОДОМ: длины,
запрещённые символы, повторы слов, наличие must-keep, отсутствие forbid.
Coverage Score (доля сохранённого поискового веса) тоже считает код, не модель.
Действия в карточке разделены на две группы с чертой между ними:
«Решение по тексту» (принять, редактировать, перегенерировать) и
«Выгрузка» (скачать flat file, отправить в Amazon) — второе с отступом,
под ним история отправок. **Основная кнопка всегда одна и показывает
следующий шаг:** не принято — «Принять», принято — «Отправить в Amazon»,
отправлено — основной нет. Наверху страницы те же выгрузка и отправка,
но по всем принятым под фильтром, и в подписи «для всех принятых · N».
Карточные кнопки до приёмки неактивны: они работают с `synthesis_changes`.

**Список один, вкладок нет.** Раньше их было три — очередь,
«Сгенерированные», любой товар, — и товар переезжал между ними после
каждого действия: сгенерировал — уехал во вторую, принял — исчез и
оттуда. Первый вопрос после приёмки был «а куда он делся». Теперь
строка остаётся на месте, меняется только метка состояния: «Без
результата» → «Сгенерировано» → «Принят» → «Отправлено».

Над списком три фильтра состояния с живыми счётчиками (считают по
текущей выборке, а не по базе): «Требуют замены», «Все» (весь каталог)
и «Отправленные» (есть удачная запись в `listing_push_log`).
**«Требуют замены» — это НЕ просто правило `title_over_limit`:** диагноз
пишется сбором и живёт до следующего, поэтому товар с уже отправленным
укладывающимся тайтлом висел в списке как несделанная работа. Удачная
отправка снимает признак сразу, не дожидаясь сбора. Фильтр
по стране и поиск работают поверх. Внутри «Требуют замены» порядок
блоками: ждут решения → решение принято → без результата, между ними
разделители с числами. Блок принятого отдельный намеренно: держать
принятое под подписью «ждут решения» — то самое враньё, ради которого
вкладки и убирали.

Строка компактная и самодостаточная: галочка, текст (результат, если он
есть, иначе нынешний тайтл), под ним SKU, ASIN, рынок, «было N», метки
«старая методология (vN)» и «нет данных поиска», справа Coverage,
состояние и длина результата. **Плашка Coverage стоит всегда**: когда
числа нет, она называет причину («не считался: нет данных поиска» или
«результат сделан до подсчёта Coverage») — пустое место на её месте
не отличало «не считался» от «сейчас появится». Карточка раскрывается под строкой и
осталась прежней. Массовые действия — одной панелью над списком, все
работают по ОТМЕЧЕННЫМ строкам текущей выборки. Отметки живут отдельным
множеством пар в `session_state`, а не в ключах галочек: галочка есть
только у отрисованной строки, поэтому «Выбрать все» физически отмечала
тридцать строк экрана при выборке в сотни. Кнопки: «Выбрать все · N»,
«Сгенерировать партию», «Принять · N» (неактивна, пока у кого-то из
выбранных нет результата), «Перегенерировать · N» с той же полосой
хода, что у партии.

Наверху — разрез по рынкам (строки складываются в итог, мелкие страны
сворачиваются в «Прочие»), в блоке результата — плашка модели, которой
он сделан, и пометка, если товар уже принимался.
Читает: `diagnosis`, `listing_snapshots`, `product_matrix`, `synthesis_skill`,
`protected_keywords`, `synthesis_drafts`, `synthesis_coverage`,
`synthesis_changes`, `sqp_reports`, `asin_economics`.
Пишет: `synthesis_drafts`, `synthesis_coverage`, `synthesis_changes`.
Все числа блока выгрузки — из одного источника (принятые под текущим
фильтром), кнопки не исчезают при нуле, а строка состояния всегда
называет фильтр: «Германия: принято 3 · строк: 3 · файлов: 1». Раньше
подпись кнопки считала строки файла, соседняя — принятые правки, и ряд
говорил о разном.
Выгрузка для Amazon — настоящий шаблон Seller Central, см.
`services/flatfile_template.py`. Рядом — прямая отправка по SP-API
(`services/spapi.py`): только по одному товару и только через диалог
подтверждения.

### `photo.py` — «Фото и A+»
Аудит визуала через vision-модель. Вкладка «Галерея» — главное фото + галерея
(методология `photo_brief`), вкладка «A+ контент» — модули A+ (методология
`aplus`). Грейд считает КОД, ИИ отвечает только по чек-пунктам (true/false)
и даёт покадровый разбор + ТЗ дизайнеру. Отдельно проверяется соответствие
языка изображений языку маркетплейса.
Читает: `listing_snapshots`, `product_matrix`, `synthesis_skill`,
`photo_analysis`.
Пишет: `photo_analysis` (`analysis_type` = `gallery` | `aplus`).

### `matrix_setup.py` — «Матрица товаров»
Ввод ASIN пачкой (терпимый парсер: `sku, asin, mp[, конкурент]`, голый ASIN,
URL Amazon), импорт из зеркала каталога, список карточек с кнопкой «Собрать»,
групповые действия, удаление, расписание автосбора.
**Здесь живёт рабочий пайплайн сбора** — `collect_rows()`: запрос к ScrapingDog
(с `country` и `language`; без `country` фолбэк «us» уводит сбор
на amazon.com и снапшот приезжает от чужого листинга, без `language`
amazon.es отдаёт EN-версию и длина тайтла считается по чужому языку) → запись снапшота → запись длин → создание болей по правилам
`out_of_stock`, `title_over_limit`, `low_reviews`, `few_images`, `no_video`,
`no_aplus`.
Читает: `product_matrix`, `listing_snapshots`, `diagnosis`, `catalog_source`,
`collection_schedule`.
Пишет: `product_matrix`, `listing_snapshots`, `listing_analysis`, `diagnosis`,
`collection_schedule`.

### `methodology.py` — «Методологии»
Библиотека скиллов с версиями. Каждая область (`scope`: `common`,
`title_split`, `bullets`, `photo_brief`, `aplus`, `ai_grade`, …) — своя
методология. Правки без коммитов кода: новая версия при каждом сохранении,
откат в один клик. Здесь же редактируются пороги правил (лимиты, min_reviews,
min_images, границы рейтинга) и ведётся реестр источников политик Amazon
с алертами об изменениях.
Читает: `synthesis_skill`, `policy_sources`, `policy_alerts`, `app_settings`.
Пишет: `synthesis_skill`, `policy_sources.last_checked`, `policy_alerts.status`,
`app_settings`.

### `settings.py` — «Настройки»
Четыре блока: статус подключений (Gemini, Anthropic, ScrapingDog,
Amazon SP-API, Lakebase — маска ключа + кнопка проверки связи; у SP-API
ключей четыре, поэтому называется каждый недостающий, а проверка дёргает
`GET /sellers/v1/marketplaceParticipations` и показывает число рынков
и подавленные листинги), выбор провайдера и модели под каждую
задачу `services/ai.py` (`title_split`, `photo_audit`, `agents`; списки
моделей тянутся живьём из API провайдеров), загрузка эталонов flat file
и ссылка на пороги правил (они живут в «Методологии»). Ключи API здесь
не хранятся и не вводятся — только в Streamlit Secrets, наружу идёт лишь
хвост ключа.
Читает и пишет: `app_settings` (через `services.settings`),
`flatfile_templates` (через `services.flatfile_template`).

## Модули (`services/`, `components/`)

### `services/db.py`
Подключение (три режима), `cfg()` для секретов, DDL и CRUD `product_matrix`,
парсер ввода `parse_asin_lines()`.
Таблицы: `product_matrix`.

### `services/settings.py`
Настройки приложения из `app_settings` (key/value) с дефолтами:
`model.*`, `provider.*`, `limit.title`, `limit.highlights`,
`threshold.min_reviews`, `threshold.min_images`, `threshold.rating_*`.
Пороги читаются через `get_int`/`get_float` с фолбэком на
[config.py](config.py). Кэш 120 c, `save_setting()` чистит кэш.
Таблицы: `app_settings`.

### `services/ai.py`
Единый слой вызова ИИ. Страницы не знают провайдера: выбор задаётся
`provider.<task>` / `model.<task>` в `app_settings`. Задачи: `title_split`,
`photo_audit`, `agents`. Поддержаны Gemini и Anthropic, вход — промпт +
опционально список URL изображений, выход — распарсенный JSON или `None`
(ошибка уже показана в UI).

Постоянная часть промпта передаётся отдельным аргументом `system`: у
Anthropic она уходит блоком с `cache_control: ephemeral` и при партии
читается из кэша, у Gemini — в `systemInstruction`. Кэш там — совпадение
ПРЕФИКСА (порядок `tools` → `system` → `messages`), поэтому всё
меняющееся от товара к товару обязано лежать в `messages`, иначе
кэшировать нечего. Проверять надо не по метке, а по расходу:
`usage_totals()` копит `cache_read_input_tokens` и показывается на
Синтезе после партии.
Таблиц не читает (только `app_settings` через `services.settings`).

### `services/economics.py`
Экономика ASIN за 30 дней: выручка, сессии, конверсия, buy box, шаблон
доставки. Плюс `RULE_RISK` — прозрачные коэффициенты «доля выручки под риском»
по каждому типу боли, и форматтеры денег/конверсии. Нужен, чтобы приоритет
шёл по деньгам, а не только по severity.
Таблицы: `asin_economics`.

### `services/seo.py`
Поисковый вес фраз и Coverage Score. Четыре типа фраз: `must_keep` (есть
покупки), `preferred` (есть клики), `compress` (только показы), `forbid`
(чужой бренд или нерелевантный запрос). Тип определяется фактами SQP без
участия ИИ; вес = покупки×200 + клики×10 + показы×0.05 + volume×0.001.
Coverage считается кодом: доля сохранённого веса от общего (кроме forbid).
Также — безопасные сжатия (`1500 mAh` → `1.5 Ah`, `milímetros` → `mm`).
Таблицы: `sqp_reports` (чтение), `protected_keywords` (запись ручных правок).

### `services/search.py`
Поисковая сводка для витрины: за 4 недели — сколько запросов, суммарный
спрос, доля показов, CTR, покупки. Одна строка на товар, в отличие от
`seo.py` с пофразовой разметкой (обе читают `sqp_reports`). CTR судится
только при `MIN_IMPRESSIONS_FOR_CTR` = 100 показов и выше: у молодого
листинга 3 клика из 12 показов — шум, а не 25% CTR; порог «кликают» —
`threshold.min_ctr` (по умолчанию 0.3%, из практики Amazon: ниже при
заметных показах карточка не убеждает), правится на странице «Методология».
Таблицы: `sqp_reports`.

### `services/attributes.py`
Товар со стороны каталога Amazon: тип товара, browse node, заполненность
атрибутов, `generic_keyword`, буллеты, описание. Пустые атрибуты не видны
глазом на листинге, но выбрасывают товар из фильтров покупателя, а пустой
`generic_keyword` — из выдачи по синонимам; это боли `few_attributes`
и `empty_keywords`. `fill_state` даёт цвет и подпись «12/27»
(`FILL_OK` = 0.85, `FILL_WARN` = 0.5), `missing_critical` — переведённый
список пробелов по важности.
Таблицы: `listing_attributes`.

### `services/serp.py`
Превью выдачи и читаемость тайтла. Считает две стороны: человеческую
(видимая часть на мобиле 60 / десктопе 110 символов, зона первого взгляда 30,
якоря-цифры, чанки, длинное слово) и машинную (пары «атрибут — значение»,
модель, число извлекаемых фактов). Рендерит карточки превью и сравнение
с конкурентами.
Таблицы: `product_matrix`, `listing_snapshots`.

### `services/worklog.py`
След работы по товару: черновики сплита, принятые правки, грейды фото и A+ —
одной картой `(asin, marketplace) → dict`. Даёт HTML-значки для строк
в Матрице и Каталоге.
Таблицы: `synthesis_drafts`, `synthesis_changes`, `photo_analysis`.

### `services/flatfile.py` и `services/flatfile_template.py`
Выгрузка принятых правок в загружаемый файл Amazon. `flatfile_template`
разбирает эталон (вкладка «Plantilla», строки 1–6 служебные, данные с 7-й),
хранит его в `flatfile_templates` со срезанными строками данных и собирает
готовый файл ХИРУРГИЕЙ ПО ZIP: подменяется ровно один XML листа, остальные
42 части архива копируются байт в байт. Пересохранение через openpyxl не
годится — теряются settings первой строки, выпадающие списки и картинки.
`flatfile` раскладывает строки по шаблонам (один шаблон покрывает 30 типов
товара из 60, диапазоны не пересекаются), даёт CSV для человека и список
непопавших строк с причиной.
Таблицы: `synthesis_changes`, `flatfile_templates`, `listing_attributes`,
`catalog_source`, `listing_issues`, `product_matrix`.

### `services/spapi.py`
Прямая отправка принятого тайтла в Amazon (`PATCH /listings/2021-08-01`).
ЕДИНСТВЕННОЕ место, которое пишет в живые листинги клиента, поэтому
модуль ничего не решает сам: диалог подтверждения и защита от повтора
живут на странице, сюда приходит уже подтверждённая ОДНА позиция.
`marketplace_id` и `language_tag` берутся из машинного имени `item_name`
в загруженном шаблоне, а не из таблицы в коде: угаданный идентификатор
рынка означает запись в чужую страну. Политика Amazon с 27.07.2026 —
тайтл сверх 75 не отправляется вовсе, Item Highlights уходят только
вместе с укладывающимся тайтлом. Журнал пишется и при успехе, и при
отказе. `check_connection()` проверяет связь до первой отправки: самый
лёгкий эндпоинт `marketplaceParticipations` проходит весь путь целиком
(refresh token → access token → подписанный запрос), и о сломанной
авторизации узнаём в Настройках, а не на живом товаре.
Таблицы: `listing_push_log` (запись и чтение).

### `services/history.py`
История по товару из трёх таблиц разом: отправки (`listing_push_log`),
принятые правки (`synthesis_changes`) и число генераций
(`synthesis_drafts`), разложенное по интервалам между приёмками —
«сколько заходов понадобилось». Новых полей не требует. Слова
«отклонено» не использует: отказ нигде не сохраняется, и
сгенерированное, не ставшее правкой, отклонённым не было.
Таблицы: `listing_push_log`, `synthesis_changes`, `synthesis_drafts`.

### `services/marketplaces.py`
Рынок Amazon: домен, ссылка на карточку, заглушка под фото. Ссылка
собиралась в девяти местах строкой `amazon.{marketplace}/dp/{asin}` —
работало по совпадению, потому что код рынка и есть доменный суффикс.
Совпадение неполное: у Бельгии код `be`, а витрина на amazon.com.be,
и ссылка вела на несуществующий сайт. Пятая карта маркетплейсов;
её согласованность с остальными проверяет `test_marketplace_maps`,
там же запрет на сборку ссылок руками.
Таблиц не читает.

### `services/cache.py`
Точечная инвалидация кэшей: группы «что поменялось → что перечитать».
Отсюда достижимы только кэши `services/*` — загрузчики внутри страниц
чистит сама страница, а кэши ЧУЖОЙ страницы истекают по TTL. Осознанный
размен: перечитать чужую страницу через пять минут дешевле, чем
перечитывать все страницы после каждого действия.

### `components/ui.py`
Визуальные компоненты и палитра: `inject_fonts()` (CSS-переменные, скрытие
служебных элементов Streamlit, адаптив и тумблер «мобильный вид»), `eyebrow`,
`verdict`, `chips_row`, `limit_ruler_html` (линейка-допуск: штриховка
превышения или прогресс к цели), `pain_card` (боль → причина → действие →
деньги).

### `i18n.py`
`LANGS` — три словаря (ru, uk, en), `t(key, **kwargs)` с фолбэком
en → сам ключ (забытый перевод виден в UI, без тихих дыр), `current_lang()`,
`lang_selector()` в сайдбаре.

### `config.py`
Константы-дефолты: `TITLE_LIMIT=75`, `HIGHLIGHTS_LIMIT=125`,
`TITLE_DEADLINE=2026-07-27`, `STALE_DAYS`, `LOW_REVIEWS_RATIO`, `MIN_IMAGES`,
`days_to_deadline()`. Рантайм-значения перекрываются из `app_settings`.

`tests/fixture_template.py` — не тест, а общая миниатюра шаблона Amazon
для двух наборов сразу: импортировать один тест из другого нельзя,
они исполняются как скрипты.

`test_ai_errors.py` — регрессия на самый дорогой класс поломок:
**ошибка провайдера обязана доходить до экрана**. Проверяет HTTP-ошибку
с кодом и телом, HTTP 200 с неразобранным телом (раньше тихий `None`),
таймаут, сброс ошибки при успехе и главное — что сообщение переживает
`st.rerun()`. Ломать эти проверки нельзя: молчаливый провал генерации
стоил часов диагностики при починке в одну строку.

`test_flatfile_export.py` — выгрузка обязана быть настоящим файлом
Amazon: служебные строки 1–6 доходят без правок, колонки ищутся по
машинному имени из строки 5, подпись частичного обновления берётся из
шаблона, а не хардкодится, строка с непокрытым типом товара попадает
в список проблем, а не теряется.

`test_synthesis_counters.py` — числа в шапке Синтеза проверяемы.
Рядом с разрезом по стране стоит общее число: пока было видно только
общее, неверный разрез выглядел бы нормально. Проверяет, что фильтр
режет ВСЕ три метрики (деньги, тайтлы, SQP), что общее от фильтра
не едет и что без фильтра «всего» не показывается.

`test_synthesis_breakdown.py` — разрез по рынкам и происхождение
черновика. Строки таблицы по странам обязаны складываться в итог —
это и есть проверка разреза. Плюс честность подписей: «Прочие»
перечисляют коды свёрнутых стран, выбранная страна не сворачивается,
плашка модели не выдумывает вендора для незнакомого имени, а история
не пишет «отклонено» — отказ нигде не сохраняется.

`test_prompt_cache.py` — кэш промпта живёт на совпадении байтов.
Половина проверок про то, что кэш работает (постоянная часть побайтово
одна на все товары, тайтл и фразы в неё не попадают), половина — что он
инвалидируется: правка методологии или смена её версии меняют байты.
Без второго генерации молча шли бы по старой методологии.

`test_push_amazon.py` — отправка пишет в ЖИВЫЕ листинги клиента,
поэтому главная проверка не «работает ли», а «не срабатывает ли сама»:
отрисовка подтверждения не шлёт ничего, кнопка на панели только
открывает диалог, запрос уходит лишь после второй кнопки. Плюс
marketplace_id только из шаблона, тайтл сверх лимита не отправляется,
Highlights не уходят без укладывающегося тайтла, журнал пишется и при
отказе.

`test_catalog_choice.py` — плашки Amazon's Choice. Три случая ломаются
тихо: NaN у несобранного товара истинный и дал бы «бейдж есть» без
данных; боль `lost_amazon_choice` живёт до следующего сбора, и красная
«потерян» рядом с вернувшимся бейджем — враньё; отсутствие бейджа
не показывается вовсе, иначе шум прячет сигнал.

`test_manual_edit.py` — ручная правка в карточке результата. Источник
в `synthesis_changes` считается по ФАКТИЧЕСКОМУ тексту, а не по тому,
что форму открывали: иначе доля ручных правок — мера попадания
методологии — врёт в обе стороны. Плюс лимит длины руками не обходится.

`test_marketplace_maps.py` — маркетплейс живёт в ЧЕТЫРЁХ независимых
картах (подписи в `i18n`, `MP_COUNTRY` и `MP_LANGUAGE` в `matrix_setup`,
`MARKETPLACE_REGION` в `spapi`), и пропуск страны в каждой молчит
по-своему. Дороже всех `MP_COUNTRY`: фолбэк «us» уводит сбор
на amazon.com, и снапшот приезжает от чужого листинга. Тест проверяет
не подписи, а согласованность карт между собой.

`test_aplus_stable.py` — A+ читается из `listing_latest.has_aplus`,
а не из последнего снапшота. Ошибка тут не выглядит ошибкой: карточка
показывает «A+ нет», Диагноз заводит боль, человек идёт делать A+,
который уже есть. Проверяются обе стороны подмены и запасной путь
для товара первого сбора.

`test_card_actions.py` — область действия кнопок. В карточке они
работают по ОДНОМУ товару, наверху — по всем принятым под фильтром,
а называются почти одинаково. Проверяется не наличие кнопок, а размер
выборки: файл из карточки содержит одну строку при трёх принятых, файл
сверху — три. Отдельно — что карточка переживает приёмку: принятый
черновик выпадает из очереди разбора, и без третьего источника
(принятая правка) кнопки «после приёмки» были бы недостижимы.

`test_history.py` — история по товару из трёх таблиц. Порядок событий
тут не косметика: по нему видно, ушла ли в Amazon последняя принятая
правка или предыдущая. Плюс заходы считаются ПО ИНТЕРВАЛАМ между
приёмками (общий счётчик завысил бы вторую), отказ Amazon не выглядит
успехом, а недоступная история отличима от пустой.

`test_silent_failures.py` — сбой не должен выглядеть как «данных нет».
Самая дорогая из запертых здесь ошибок: сбой чтения SQP превращал
генерацию в работу вслепую — `keep=[]`, `forbid=[]`, `keeps_all` на пустом
списке проходит сам собой, тайтлы получаются в лимите и с зелёными
галочками, а поискового веса в них нет. Плюс `float(x or 0)` на NaN даёт
NaN, а не ноль, и правило без коэффициента больше не получает 3% выручки.

`test_methodology_guard.py` — генерация без методологии не запускается.
Инцидент 29.08: в тайтлы вернулся бренд, хотя активная v8 его запрещает.
Кэш промпта был ни при чём — в `load_skill()` жила ЗАПАСНАЯ методология
с зашитым «Бренд Dnipro-M первым», то есть с правилом, прямо
противоположным действующему. Включалась молча, уходила в промпт
с версией 0, и всё выглядело нормально. Запасной больше нет никакой,
версия 0 означает отказ.

`test_progress.py` — ход генерации виден, старый результат не мигает.
Дольше всего идут автоповторы, и раньше они шли молча: экран замирал,
и было не понять, работа идёт или сломалось. Проверяется не наличие
строк, а фактическая последовательность шагов, номер повтора с
превышением, и что сломанный показ хода не роняет саму генерацию.

`test_no_deprecations.py` — лог не должен зарастать предупреждениями.
Смысл не в аккуратности: предупреждения шли на каждый запрос, и в этом
шуме не видно настоящих ошибок. Проверяется грепом по исходникам —
важно не «работает», а «нигде не осталось»; плюс отдельно то, что
pandas через движок действительно молчит (остальные тесты подменяют
`pd.read_sql` и этого бы не увидели).

`test_i18n_sync.py` — словарь и его рассинхрон с кодом. Паритет по

«интерфейс новее модулей, нужен ребут». Судить по промахам `t()` нельзя,
и это заперто отдельной проверкой: первая версия детектора считала
промахи и объявила ребут на ровном месте — на штатных пробах вроде
`issue.code.100232`. Ложная тревога здесь дороже молчания: после неё
настоящую не воспримут всерьёз.

`test_methodology_page.py` — методология обязана доходить до экрана.
Инцидент 30.08: страница для ЛЮБОЙ области показывала «методологии ещё
нет» при живой v8 в базе — в загрузчике остался `conn.close()` от
прежнего способа чтения, и NameError уходил в общий `except`. Дороже
самой невидимости то, куда страница вела дальше: пустой редактор и
кнопка «Сохранить как v1», то есть сбой чтения подводил к ПОТЕРЕ
методологии. Теперь при сбое чтения редактор и сохранение заперты.

`test_feed.py` — одна лента вместо трёх вкладок. Главная проверка не
«есть ли фильтры», а ПОСТОЯНСТВО СТРОКИ: принятый товар обязан остаться
в списке, изменить только метку и не сдвинуть счётчик. Отдельно заперты
два места с тихим враньём: «Выбрать все» берёт строки текущей выборки,
а не весь каталог (иначе «Перегенерировать» ушло бы на девятьсот
товаров вместо десятка на экране), и массовое «Принять» не включается,
пока у части выбранных нет результата — иначе кнопка обещает принять N,
а принимает меньше.

`test_length_guard.py` — гарантия лимита: запас в промпте, автоповтор,
обрезка по границе слова, отказ резать при потере must_keep.

## Деплой: когда нужен ребут Streamlit Cloud

**После мержа PR, который добавляет новые публичные символы в `services/*`
или новые ключи в `i18n.py`, приложение надо ребутнуть** (Manage app →
Reboot app). Streamlit Cloud подтягивает свежие файлы, но процесс живёт
дальше и держит уже импортированные модули в `sys.modules` — их он
не перечитывает. Страница получает новый код, а `services.ai`,
`services.settings`, `i18n` остаются старыми.

Как это выглядело три раза подряд:

| что видели | на самом деле |
|---|---|
| сырые ключи вместо переводов (`catalog.h_not_collected`) | страница новая, `i18n` старый |
| старый интерфейс при свежем коде на сервере | залипшая сессия и модули |
| `ImportError: cannot import name 'last_call_error'` | `pages/synthesis.py` новый, `services/ai.py` старый |

Симптом всегда один и тот же: **рассинхрон страницы и модуля**. Лечится
ребутом за полминуты, ищется — часами, поэтому сайдбар теперь называет
его сам: `stale_modules()` в [app.py](app.py) сравнивает ключи файла
`i18n.py` с ключами загруженного модуля и при расхождении показывает
«интерфейс новее модулей … нужен ребут».

Оборачивать импорты в `try/except ImportError` с заглушкой НЕ НАДО:
заглушка прячет рассинхрон и делает следующую поломку тихой, а тихие
поломки в этом проекте обходятся дороже самих поломок.

## Данные Amazon: известные особенности

Пять мест, где данные Amazon означают не то, что написано. Каждое уже
стоило ошибочных выводов — учитывать при любой работе с этими полями.

**1. Уровень серьёзности от Amazon недостоверен.** EPR приходит как
`WARNING` и при этом снимает листинг с продажи; ошибки языка атрибутов
помечены `ERROR` и не влияют ни на что. Судить по `severity` из
`listing_issues` нельзя — надёжен только признак покупаемости
(`asin_state`, при его отсутствии `is_buyable`). В коде `severity`
не участвует в выборе цвета вообще: см.
[services/issues.py](services/issues.py) (`_summary`) — поле читается
из таблицы, но в логику не попадает.

**2. Ранг брать из подкатегории, а не из широкой группы.** Amazon
отдаёт строку вида «nº 1.234 en Bricolaje y herramientas, nº 12 en
Sierras circulares». Первое число — широкая группа: у десятка разных
товаров оно почти одинаковое и ничего не различает. Значимо последнее,
самое узкое. Поэтому парсер берёт ПОСЛЕДНЮЮ пару найденных совпадений
(`m[-1]`), а не первую — [pages/catalog.py:131](pages/catalog.py:131).
Ключ и формат строки зависят от языка страницы, отсюда регулярки вместо
обращения по имени поля.

**3. Нулевой остаток — не всегда причина подавления.** При нулевом
остатке Кабинет всегда пишет `suppression_cause = out_of_stock`, даже
если листинг лежит из-за EPR: сток кончился как следствие простоя, а не
как причина. По самому `out_of_stock` боль в Диагнозе не создаётся
(дубль с правилом по остаткам), поэтому замаскированная блокировка
раньше не давала боли вовсе — товар отгружали на склад, а листинг
не вставал. Теперь причина ищется по кодам строк пары
(`_masked_cause` в [services/issues.py](services/issues.py)).

**4. Бренд в тайтле Amazon вырезает.** Проверено на живой отправке
17557000 / es (29.08.2026, submissionId d9dbad06…): отправили
`Dnipro-M BH-20 Martillo Percutor…`, применилось `BH-20 Martillo
Percutor…`. Бренд Amazon берёт из поля `brand` и показывает ссылкой
на магазин, а из `item_name` убирает. Значит место под бренд в 75
символах тратится впустую, и на первом месте должна стоять ключевая
фраза, а не код модели. Учтено в методологии с версии 7.

Следствие для кода, которое надо держать в голове: если бренд попадёт
в `must_keep` по фактам SQP (`services/seo.py`), проверка `keeps_all`
в [pages/synthesis.py](pages/synthesis.py) будет требовать его в тайтле,
методология — запрещать, и генерация уйдёт в автоповторы. Сейчас
конфликт не наблюдался, но при росте покупок по брендовым запросам
он появится.

**5. Признак A+ в одном снапшоте недостоверен.** ScrapingDog врёт про
`aplus` примерно на 15% запросов, а на .it по отдельным товарам на
половине. Поэтому источник истины — `listing_latest.has_aplus`
(стабилизация по трём последним снимкам), а сырое поле остаётся только
запасным для товара первого сбора. Читают вью: `catalog.metrics()`,
правило `no_aplus` в `matrix_setup.collect_rows()` (обязательно ПОСЛЕ
записи снапшота — вью считает по нему) и страница «Фото», где то же
поле различает «A+ нет» и «A+ есть, но модули не пришли».

Молчание этой ошибки дороже её самой: карточка показывает «A+ нет»,
Диагноз заводит боль, человек идёт делать A+, который уже есть.

**Строки «нет товара» в реплике не существует.** Проверено запросом:
у пар с `suppression_cause = out_of_stock` встречаются только коды
настоящих проблем (18448, 100530, 100390, 18320). Сравнивать дату
блокировки «с моментом обнуления» не с чем — в данных этого момента нет.

**Признак покупаемости принадлежит листингу, а не строке.** `is_buyable`
и `asin_state` дублируются во всех строках пары, поэтому «код X стоит
на N непокупаемых строках» означает соседство с настоящей причиной,
а не блокировку этим кодом. Так, 18448 (атрибуты) стоит на 276 парах,
из них заблокированы 20 — 93% листингов с ним продаются; он в
`BENIGN_CODES`. Судить о блокирующей способности кода по агрегату
`count(*) FILTER (WHERE is_buyable IS FALSE)` нельзя — нужен срез по
парам, где код единственный.

**Неизвестный код считается блокирующим.** Amazon пополняет список
кодов без предупреждения; молчать про незнакомый код опаснее, чем
показать лишнюю боль с действием «Открыть Fix Listing». Явно безобидные
перечислены в `BENIGN_CODES`.
