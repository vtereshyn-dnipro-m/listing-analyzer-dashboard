# CLAUDE.md

Listing Suite — Streamlit-приложение диагностики Amazon-листингов бренда
Dnipro-M. Данные — Databricks Lakebase (Postgres), схема `listing_data`.
Интерфейс на трёх языках: ru / uk / en.

Запуск: `streamlit run app.py`

**HTTP-маршрутов в приложении нет, и это проверено, а не
предположено.** Streamlit ≥ 1.64 умеет `st.App("app.py", routes=…)` —
поддерживаемый способ добавить свой маршрут рядом со страницами (не
внедрение во внутренности: между версиями сервер сменил Tornado на
Starlette). Так 16.09 поднимался `GET /figma/translations` для
плагина Figma, и живьём он работал. Снят на следующий день: на
Streamlit Cloud приложение закрыто авторизацией, и прокси отвечает
303 на `share.streamlit.io/-/auth/app` ДО того, как запрос дойдёт
до маршрута. Публичного маршрута у приватного приложения на Cloud
не бывает. Маршрут, до которого никто не дойдёт, — механизм,
который выглядит работающим, но не работает; вернуться к нему
можно только вместе с решением, где он будет жить (отдельный
сервис или публикация через Drive, см. `content.py`).

Логика продукта: матрица товаров → сбор снапшота (ScrapingDog) → диагноз
(боли по правилам) → синтез правки (ИИ + проверки кодом) → принятая правка
→ снова сбор. Человек добавляет товары и принимает правки, остальное — код.

## Автономия (предложение 19.10.2026; действует с мержа этого раздела владельцем)

Работа идёт циклами по [TASKS.md](TASKS.md). У каждой задачи там есть
уровень — **сам**, **ждёт меня** или **никогда сам** — и проверяемый
критерий готовности. Схема целиком и почему она такая —
[docs/autonomy.md](docs/autonomy.md). Скопирована с Кабинета
(kabinet-dashboard PR #328), правила Listing Suite — свои.

Уровень определяется по ИЗМЕНЕНИЮ, а не по задаче. Если PR задевает хоть
один файл уровнем выше «сам», он целиком «ждёт меня». Сомневаешься —
выбирай уровень выше. Правило «мерж — только по команде владельца»
остаётся в силе для всего, кроме уровня «сам».

**Сам** — мержу без команды, если проверяющий дал «ок» и CI
(`.github/workflows/ci.yml`) зелёный на последнем коммите PR. Без зелёного
CI проверяющий «ок» не ставит. Каждое такое слияние названо в сводке цикла:

- `docs/` — только ДОБАВЛЕНИЕ строк: новый факт или новый файл области.
  Изменение или удаление существующих строк — «мержи»: там записаны
  решения владельца;
- `TASKS.md` — новые задачи, статусы, PR, заметки. Уровень задачи агент
  может только поднять;
- комментарии в коде без изменения поведения;
- недостающие переводы в `i18n.py`, если смысл фразы не меняется: третий
  язык к существующему ключу или ключ, который код уже спрашивает;
- проверочные скрипты в `scratchpad/`, которые только читают.

Без мержа и без команды можно — это не изменения:

- чтение данных и логов;
- прогоны тестов;
- открытие PR;
- сборка сводки цикла `scratchpad/cycle_report.py`. Пока канал записи не
  выбран (TASKS.md, T-1), скрипт только печатает сводку и ни к чему не
  подключается.

**Ждёт меня** — только по «мержи #N». Выкладка, как раньше, — после мержа:

- код страниц, `services/`, `components/`, `auth.py`, `app.py`,
  `requirements.txt`;
- **миграции SQL**: файл прямо в `migrations/` — PR. Применяет агент, но
  только по команде владельца «применяй <имя файла>» (решение 21.10.2026), и
  только под учёткой владельца в Databricks — профиль CLI, через
  `scratchpad/apply_migration.py`, — а НЕ под `claude_code_ro`. Порядок:
  - предпроверка без изменений: кто подключён и какая база;
  - файл до `COMMIT` одной транзакцией;
  - проверочные запросы из конца файла — в сессии только на чтение, результат
    владельцу.

  Ошибка — `ROLLBACK` и текст ошибки владельцу. Без команды не применяется
  ничего. Скрипт отказывается:
  - если учётка CLI — не владельца;
  - на файле не одной транзакцией;
  - на `migrations/kabinet/` — SQL базы Кабинета, его применяет только
    владелец;
  - на удалении данных и `DROP` (см. «Никогда сам»), кроме пересоздания
    триггера.

  Пересоздание триггера разрешено владельцем (21.10.2026): `DROP TRIGGER IF
  EXISTS X ON T`, затем `CREATE TRIGGER X … ON T` настоящим оператором того же
  файла до `COMMIT`, таблица `listing_data.<имя>`, без `RENAME`/`SET SCHEMA` — это
  проверяет скрипт. Любой другой `DROP` и удаление данных — «никогда сам». Чего
  скрипт не видит (держит ревью PR): код строкой — в `EXECUTE '…'` и иных формах,
  кроме тела функции и `DO` (там отказ); выключение защиты без `DROP` (`ALTER
  TABLE … DISABLE TRIGGER`, замена функции или события триггера, `WHEN (false)`);
- правка `scratchpad/apply_migration.py` — он пишет в базу, поэтому не «сам»;
- **ребут Streamlit Cloud** — делает владелец; агент только напоминает;
- обновление снимка канона прогоном `canon/build_snapshot.py` по новому
  архиву от Ярослава и перегенерация `REFERENCE_DRIFT.md`;
- ноутбуки и задачи Databricks — по прямому слову и с бэкапом рядом;
- включение флагов Паспорта (этап 7, отдельные квитанции);
- правила в этом файле, изменение и удаление существующих строк `docs/`,
  `docs/autonomy.md` целиком;
- `.claude/agents/` (проверяющим агент мог бы ослабить собственную
  проверку), `.claude/settings.json`, хуки, `.gitignore`, правка
  `scratchpad/cycle_report.py`;
- удаление веток, в том числе старых;
- репозиторий Кабинета, включая источник `access_screen.py`.

**Никогда сам** — только владелец своими руками или с отдельного явного
согласия названного человека. Агент готовит план или черновик:

- **канон Ярослава** (`canon/ai_design_conveyor/`, `canon/MANIFEST.json`) —
  только чтение, правка руками запрещена. Расхождения называются в
  `REFERENCE_DRIFT.md` и уходят ему;
- **отправка в Amazon**: SP-API `PATCH` листинга, выгрузка flat file в
  Seller Central — пишет в живые листинги клиента;
- **вызовы моделей и всё, что тратит деньги или невосполнимую квоту**:
  - генерация, перегенерация и партии Синтеза;
  - перевод моделью;
  - аудит фото и A+;
  - агенты Паспорта;
  - сбор ScrapingDog и запуск задачи «Listing Suite Auto Collector»;
  - запросы к Figma (6 в месяц на месте View).

  Тесты подменяют провайдера — это разрешено и нужно;
- значения секретов: чтение, запись, перевыпуск;
- режим входа `ls_auth_enabled`, роли и права в `app_users` /
  `app_permissions`;
- удаление таблиц и данных (DROP, очистка таблицы, DELETE без условия) —
  держит ещё и хук `.claude/hooks/guard.py`. Исключение одно — пересоздание
  триггера в миграции (см. «Ждёт меня» → миграции SQL);
- **любая запись в базу под ролью `claude_code_ro`** — ни через MCP-сервер
  `lakebase-listing`, ни мимо него, тем же паролем из любого клиента.
  Запрет — правилом, несмотря на фактические права. У роли есть `UPDATE` и
  `DELETE` на `product_matrix` и `UPDATE` на `diagnosis` (T-19). Владелец
  решил права не менять (20.10.2026), поэтому граница держится не грантами,
  а этим правилом и защитой сервера: разбор запроса и сессия только на
  чтение. Роль — для чтения, и только;
- сообщения людям, кроме сводки в бот владельцу, — в том числе вопросы
  Ярославу: их отправляет владелец;
- обход проверок, `--force` в `main`, мерж своего PR с замечаниями
  проверяющего.

**Цикл.**

1. Прочитать `TASKS.md` и открытые PR.
2. Взять задачи по порядку. «Ждёт меня» — довести до PR с честным «что
   проверено, что нет» и остановиться.
3. На каждый PR — проверяющий `.claude/agents/pr-reviewer.md`, отдельным
   агентом, не автором. Вердикт «ок» или «замечания» — комментарием в PR.
   Замечания исправить и проверить заново.
4. Смержить только уровень «сам» с вердиктом «ок».
5. Обновить `TASKS.md`.
6. Сводка в бот: `scratchpad/cycle_report.py`.

Сводка уходит в тот же бот, что у Кабинета: отправляет задача Кабинета
«Kabinet - Agent Cycle Report», секрета бота агент не касается. Чужих
учётных данных агент не берёт: роль Кабинета из его `.mcp.json` для
сводки запрещена (19.10.2026). Канал записи выбирает владелец
(`docs/autonomy.md`, «Канал записи сводки»). До решения сводка печатается
и кладётся в ответ владельцу.

**Окна без мержа — 09:30–11:30 и 16:00–17:30 по Киеву** (решение владельца
21.10.2026). Действуют для ЛЮБОГО мержа: и для уровня «сам», и по команде
«мержи #N». Перед каждым мержем — проверить время (`TZ=Europe/Kyiv date`).

## Правила проекта

Выстраданы на практике: нарушение каждого уже роняло страницу. Механика и
истории — [docs/rules.md](docs/rules.md).

**0. Плотный ряд кнопок — флексом, а не долями `st.columns`.** Колонке
`flex:0 0 auto; width:auto`, кнопке `width:auto`, последней колонке
`flex:1 1 auto`. Эталон — `.st-key-rescard-*` в [pages/synthesis.py](pages/synthesis.py).

**1. HTML внутри `st.markdown` — ОДНОЙ строкой**, без переносов и отступов:
конкатенация f-строк. Эталон — [components/ui.py](components/ui.py)
(`pain_card`, `verdict`, `limit_ruler_html`).

**2. `MONO = "var(--ls-mono)"`** (CSS-переменная из `inject_fonts()`): кавычек
внутри HTML-атрибутов быть не должно.

**3. Имена колонок DataFrame — технические латиницей** (`img`, `len`, `risk`,
`link`); человеческие подписи — ТОЛЬКО через `column_config`. Иначе дубли имён
после перевода роняют pyarrow.

**4. `pd.isna(x)`, а не `if x`; `x or ""` на ячейке pandas запрещён** — NaN
истинный. Строка из ячейки — `cell_text()` из [services/cells.py](services/cells.py),
запирает `test_silent_failures`. Фикстура повторяет НАСТОЯЩУЮ форму данных (NaN,
а не `""`). Словари из JSON под правило не попадают.

**5. Все видимые строки — через `t()`** из [i18n.py](i18n.py); наборы ключей и
плейсхолдеры ru / uk / en совпадают (`test_i18n_sync`). Где промах перевода
штатен (подписи болей по `rule_id`, коды Amazon) — `i18n.tr_opt(key)`, не `t()`.

**6. Палитра:**

| роль | цвет |
|---|---|
| фон | `#FAFAF8` |
| чернильный (текст) | `#1A1815` |
| акцент (только для боли) | `#E8590C` |
| зелёный (норма) | `#2F6B3A` |
| приглушённый | `#57534A` |
| границы | `#E7E4DD` |

Та же палитра — в [.streamlit/config.toml](.streamlit/config.toml) и в константах
наверху каждой страницы.

**7. Виджет выбора с переводимыми подписями хранит значение ОТДЕЛЬНО** — кодами в
своём ключе; колбэк игнорирует значения, которых нет в опциях. Эталон —
`sticky_select` в [pages/synthesis.py](pages/synthesis.py).

**7б. Виджет с `key` игнорирует `value`, и `pop` этого не лечит.** Работает только
другой `key`: «поколение» данных в `session_state`, подмешанное в ключ, растёт
после записи. Писать в `session_state[ключ_виджета]` после создания виджета
нельзя (`StreamlitWidgetAlreadyInstantiatedError`) — кнопка кладёт набор и растит
поколение. Эталоны — `loc-gen-*`, `_translate_rows`, `pick_langs` в
[pages/content.py](pages/content.py), `new_result()` на Синтезе.

**8. Фильтр один, и его слушает весь экран.** На измерение — один переключатель;
список, счётчики, выгрузка и массовые кнопки берут ОДНУ выборку из одной функции
фильтра страницы (`apply_filters`, `base_rows`). Счётчик в подписи фильтра — под
остальными фильтрами; шапка и выгрузка над фильтрами держат место `st.container()`;
итог «по всей базе» под фильтром не показывается; опции — по всей базе. Ключи
`session_state` у каждой страницы — со своим префиксом (`test_filters_one_source`).

## Вход через Google и роли (с 02.10.2026)

Подробно — [docs/auth.md](docs/auth.md).

- **Всё про «кто и что можно» — в `auth.py`**, по образцу Кабинета: три режима,
  `can()` / `require()` / `demand()`, `guard()` в `app.py` ДО `st.navigation`,
  закрытая страница — скрытая заглушка с тем же адресом.
- **Люди и права — в базе КАБИНЕТА** (`services/kdb.py`): `app_users` с двумя
  ролями (`role` — Кабинет, `ls_role` — Listing Suite) и `app_permissions`, строки
  `ls.*`. Своей копии списка людей здесь нет. Справочник SKU Паспорта — оттуда же,
  только чтение.
- **Listing Suite никого не заводит**: незнакомая почта — отказ и одно сообщение
  администраторам за сессию; роль назначает человек в «Кабинет → Доступ».
- **Режим — свой** (`reorder_params.ls_auth_enabled`): 2 раскатка, 1 вход
  обязателен, 0 авария. Нет строки или база недоступна — 2, но причина обязана дойти
  до лога, сайдбара и «Настройки → Вход и роли»: молчащий вход — поломка.
- **Роли:** Просмотр · Контент-менеджер · Утверждающий · Администратор и роль пилота
  `textgen_pilot`: одна страница — генератор — и одно действие, `ls.textgen.accept`
  ([docs/textgen.md](docs/textgen.md)).
  Действия: `ls.content.edit`, `ls.amazon.push` (утверждающий и выше),
  `ls.method.edit`, `ls.settings.edit` (администратор), `ls.admin` (экран «Доступ»),
  `ls.textgen.accept` (администратор и пилот), `ls.page.*`. **Новое действие `ls.*`
  заводится В ТОМ ЖЕ коммите строкой в `app_permissions`**, иначе кнопка не
  заработает ни у кого.
- **Проверка — в обработчике нажатия, а не на отрисовке кнопки**; отклонённые
  попытки пишутся в журнал. У колбэков свой путь отказа (`_may_edit_cb()` на
  «Контенте»): из колбэка `st.error` на экран не попадает.
- **Синтаксис проверяется `compile`, а не `ast.parse`**: `return` в обработчике
  верхнего уровня `ast.parse` пропускает.
- **`access_screen.py` — выкладка из репозитория Кабинета байт в байт.** Править у
  источника и выкладывать его скриптом; правку копии ловит
  `tests/test_access_screen_copy.py`.
- **Правка секретов требует ребута**, не перезахода. Зависимости входа — сразу обе:
  `Authlib>=1.3.2,<2` и `httpx`.

## Подключение к данным

Подробно — [docs/data-access.md](docs/data-access.md).

- **`services/db.py::get_conn()` — единственная точка входа для записи,
  `get_engine()` — для чтения через pandas.** Голое psycopg2-соединение в
  `pd.read_sql` не передаётся. Режимы: ноутбук Databricks, Streamlit Cloud (секция
  `[databricks]`), локально `DATABASE_URL`. `search_path` — `listing_data, public`.
- **Соединения — в пуле**, токен — в `@st.cache_resource` на 50 минут, повтор со
  свежим токеном на отказ авторизации — ровно один. `get_conn()` отдаёт
  `PooledConnection`: `with conn:` — КОММИТ без закрытия, как у psycopg2
  (`test_db_pool.py`).
- **Правило DDL: миграции идут через Databricks, по команде владельца.** Каждая —
  отдельный `.sql` в [migrations/](migrations/), см. [migrations/README.md](migrations/README.md);
  применяет агент по команде «применяй <имя файла>», под учёткой владельца (раздел
  «Автономия»). Приложение схему не создаёт и не меняет — только `SELECT` и
  разрешённые `INSERT`/`UPDATE`.
- **Код и миграция едут порознь, и код обязан это переживать**: новая колонка —
  через `missing_columns()`, без неё страница работает по старой схеме и называет
  недостающую миграцию. Тест страницы проверяет обе схемы, фикстура «без миграции»
  ПАДАЕТ на новой колонке, как база.
- **Секреты — через `services.db.cfg(name)`**: env → `.streamlit/secrets.toml` →
  `st.secrets` → default.

## Страницы (`pages/`)

Регистрируются в [app.py](app.py) через `st.navigation`: «Работа» (guide, dashboard,
catalog, synthesis, photo, content, textgen) и «Управление» (matrix_setup,
methodology, settings). Подробно о каждой — [docs/pages.md](docs/pages.md).

- **`guide.py` — «Как это работает»**: инструкция и живая схема потока.
- **`dashboard.py` — «Диагноз»** (по умолчанию): шапка и выгрузка — по фильтрам
  (правило 8); деньги под риском — максимум по товару, не сумма; боли Issues —
  с кешем по языку.
- **`catalog.py` — «Каталог»**: возраст данных — по правилам сбора
  (`collection_tier`, `weekly_day`, `wound_down`), а не по календарю; рынок
  выбирается ОДИН раз галочками, по ним список, выгрузка и сбор; сбор — job
  «Listing Suite Auto Collector» из приложения, не поверх идущего run'а; выгрузка —
  ровно то, что на экране. Правила `buy_box_lost` НЕТ намеренно.
- **`synthesis.py` — «Синтез»**: закладки — по виду текста и площадке, не по
  состоянию; «черновика» в UI нет — «результат»; **запасной методологии в коде нет**:
  нет методологии — генерации нет; результат проверяет КОД; основная кнопка
  показывает следующий шаг; список один, строка не переезжает; массовые действия —
  по отмеченным строкам текущей выборки.
- **`photo.py` — «Фото и A+»**: грейд считает код, модель отвечает по чек-пунктам;
  несобранные пары названы под списком.
- **`content.py` — «Контент»**: перевод макетов Figma и «Паспорт SKU». Демо всегда
  объявляется плашкой; правка уезжает в базу сразу; отказ модели доходит до экрана;
  строки — от английского исходника по `slot`; в Figma пишет только плагин
  ([figma-plugin/](figma-plugin/)); квота Figma — по правилам `services/figma.py`.
- **`textgen.py` — «Генератор текстов (пилот)»**: [docs/textgen.md](docs/textgen.md).
- **`matrix_setup.py` — «Матрица»**: здесь рабочий пайплайн сбора `collect_rows()`;
  запрос к ScrapingDog — только с `country` и `language`.
- **`methodology.py` — «Методологии»**: версии без коммитов; при сбое чтения
  редактор и сохранение заперты.
- **`settings.py` — «Настройки»**: ключи только в Secrets, наружу — хвост; список
  задач ИИ — в `DEFAULTS` (`services/ai.py`) и `TASKS`, согласованы тестом.

## Модули (`services/`, `components/`)

Подробно — [docs/modules.md](docs/modules.md), плюс файлы областей:
[docs/title-rules.md](docs/title-rules.md), [docs/product-specs.md](docs/product-specs.md),
[docs/textgen.md](docs/textgen.md).

- **`services/spapi.py` — ЕДИНСТВЕННОЕ место, которое пишет в живые листинги.**
  Ничего не решает сам: подтверждение и защита от повтора — на странице, сюда
  приходит уже подтверждённая ОДНА позиция (на Синтезе — только по одному товару и
  только через диалог подтверждения);
  `marketplace_id` — из загруженного шаблона, не из таблицы в коде. Тайтл сверх 75
  не отправляется вовсе; Item Highlights — только вместе с укладывающимся тайтлом;
  журнал `listing_push_log` — и при успехе, и при отказе.
- **`services/ai.py`** — единый слой вызова ИИ. **Ошибка провайдера обязана дойти до
  экрана** и пережить `st.rerun()` — `test_ai_errors.py` ломать нельзя. Постоянная
  часть промпта — в `system` (кэш — совпадение префикса), меняющееся — в `messages`.
- **`services/db.py::safe_read()`** — «пусто» отличается от «сломалось»;
  `table_exists()` — «нет таблицы» от «пустая».
- **`services/cache.py`** — точечная инвалидация, ковровый сброс — только где данные
  общие.
- **`services/title_rules.py`**, **`services/product_specs.py`**, **`services/seo.py`**
  (вес фраз и Coverage считает код), `search.py`, `attributes.py`, `serp.py`,
  `worklog.py`, `flatfile*.py` (выгрузка — хирургия по ZIP), `history.py`,
  `marketplaces.py` (ссылки на Amazon — только отсюда), `figma.py`,
  `translate.py`, `localization.py`, `passport*.py`, `passport_copies.py` (копия
  паспорта docx в томе UC), `graph_*.py` (ядро движка графа: условие ребра —
  грамматика, а не `eval`; запись перехода — только с квитанцией бюджета), `economics.py`,
  `settings.py`, `components/ui.py`, `i18n.py`, `config.py`.

## Тесты (`tests/`)

Скрипты, не pytest. Весь набор — `python tests/run_all.py` (слова после команды —
фильтр по имени файла). Список и что запирает каждый — [docs/tests.md](docs/tests.md).

- **CI** (`.github/workflows/ci.yml`, с 19.10.2026) гоняет тот же `run_all.py` на каждый PR и пуш в
  `main`. Базы и секретов в CI нет и не будет — репозиторий публичный; всё внешнее
  подменено в тестах. **Тест, падающий только без секретов, — поломка теста.**
- Сквозные проверки: `test_syntax.py` (`compile` каждого `.py`), `test_imports.py`
  (импорт модулей в пустом окружении), `test_i18n_sync.py` (паритет переводов).
- Так написаны наборы проекта: проверяется поведение, а не наличие строк, и, где
  можно, мутация того, что запирается, валит проверку ([docs/tests.md](docs/tests.md)).
  Фикстура повторяет настоящую форму данных (правило 4).
- Новый тест — строкой в список и абзацем в [docs/tests.md](docs/tests.md).

## Деплой: когда нужен ребут Streamlit Cloud

Подробно — [docs/deploy.md](docs/deploy.md).

- Новые публичные символы в `services/*` или ключи в `i18n.py` — ребут (Manage app →
  Reboot app), пока не подтверждён `deploy_sync` (T-16): новый номер «Версия кода» в
  сайдбаре после мержа без ребута — признак, что он работает. Ребут делает владелец.
- Ребут нужен всегда, даже когда `deploy_sync` подтверждён: менялся сам
  `deploy_sync.py` (он себя не выгружает) или сайдбар пишет «интерфейс новее модулей».
- Симптом рассинхрона страницы и модуля сайдбар называет сам (`stale_modules()`).
- **Импорты в `try/except ImportError` с заглушкой не оборачивать**: заглушка прячет
  рассинхрон.

## Данные Amazon: известные особенности

Каждая уже стоила ошибочных выводов. Подробно — [docs/amazon-data.md](docs/amazon-data.md).

1. `severity` из `listing_issues` недостоверен — надёжна только покупаемость
   (`asin_state`, иначе `is_buyable`).
2. BSR — из самой узкой подкатегории (последняя пара), не из широкой группы.
3. Нулевой остаток — не всегда причина подавления (`_masked_cause`).
4. Бренд из начала `item_name` Amazon вырезает (живая отправка 29.08.2026).
5. Признак A+ одного снапшота недостоверен — источник `listing_latest.has_aplus`.

Неизвестный код Issues считается блокирующим; безобидные — в `BENIGN_CODES`.
