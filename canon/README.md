# Канон AI Design Conveyor — снимок для «Контент → Паспорт SKU»

Здесь лежит КОПИЯ части канона конвейера AI Design, по которой Listing Suite
строит область «Паспорт SKU»: нормативы Паспорта, граф исполнения, контракты
Listing Suite, схемы и фикстуры. Канон ведёт владелец процесса AI Design
(Ярослав), и его решение записано прямо: **ИИ в каноне ничего не меняет и не
добавляет**. Поэтому:

- `ai_design_conveyor/` — байт в байт из архива владельца, руками не правится.
  Правку ловит `tests/test_canon_snapshot.py` по SHA-256 из манифеста;
- `MANIFEST.json` — путь, SHA-256, размер и версия из шапки каждого файла,
  плюс SHA самого архива, из которого снимок собран;
- `build_snapshot.py` — единственный способ обновить снимок: новым прогоном по
  новому архиву. Правила отбора — в его docstring;
- `check_references.py` → `REFERENCE_DRIFT.md` — где документы канона
  ссылаются на версию или SHA соседа, которые расходятся с самим файлом, и где
  реестры графа не дотягивают до своего контракта. Канон не чиним — отчёт
  уходит владельцу, а код берёт ФАЙЛ из снимка, не версию из ссылки
  (договорённость 07.10.2026).

Обновление:

```
python canon/build_snapshot.py "<путь к AI Design Conveyor.zip>"
python canon/check_references.py
```

Какие версии берутся: из нескольких версий одного документа — последняя.
Старые остаются только там, где новая наследует их «byte-addressed», то есть
ссылается на родителя по SHA (06F: v1.3 ← v1.2 ← v1.1 ← v1.0) — без родителя
набор не исполним. Архивы (`_archive`, `99_Archive`, `_rollback`), эскизы PNG,
docx-копия ТЗ v1.0 (тот же текст лежит в markdown) и историческая конфигурация
FULL (05–05C, Координатор её исключает) в снимок не входят.
