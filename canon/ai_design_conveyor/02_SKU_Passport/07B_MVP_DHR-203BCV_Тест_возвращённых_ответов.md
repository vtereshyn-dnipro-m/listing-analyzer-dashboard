# Тест обработки возвращённых ответов DHR-203BCV

## Цель

Проверить, как Собиратель и Верификатор должны обработать ответы после выдачи нумерованных вопросов, не редактируя Паспорт автоматически.

## Ожидаемая работа Собирателя

1. Принять ответы только по точным `question_id`.
2. Зарегистрировать каждый источник и локатор.
3. Не заменять вопрос похожим найденным фактом.
4. Подготовить candidate updates для подтверждённых характеристик отдельно от ответа на вопрос.
5. Для Q-001 создать/сохранить conflict между bare tool и KIT, а не выбрать одну версию.
6. Не менять статус вопроса на `CLOSED` самостоятельно.
7. Вернуть delta package Верификатору.

## Результат теста

Текущая инструкция Собирателя в целом поддерживает delta-обновление, сохранение gap IDs, `answer_added`, conflict и candidate update. Однако без отдельного реестра 06E она не гарантировала стабильную адресацию вопросов и однозначную классификацию частичных ответов.

После введения 06E рабочий цикл становится понятным:

`вопрос с постоянным ID → ответ с answer_id → проверка scope/evidence → candidate update/conflict/no change → повторная оценка Верификатора → CLOSED или новый связанный вопрос`.

Паспорт не меняется в этом цикле. После ручного решения отдельный процесс обновления применяет одобренный candidate update.
